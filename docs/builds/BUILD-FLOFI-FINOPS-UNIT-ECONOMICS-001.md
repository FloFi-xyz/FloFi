## Financial evidence

The 10 bps universal route fee exists as a recorded obligation with collection state `NOT_SETTLED`. It carries no evidence of FloFi receiving funds. Transaction estimates, steps and user-paid gas do not establish revenue, fee-eligible volume, or operating expense. Actual revenue, variable-cost coverage and realized contribution margins therefore depend on reconciled records. The infrastructure-adjusted operating result excludes corporate overhead and is a different measure from corporate profit.

Provider inventory was reconciled against the deployment contracts for Neon PostgreSQL and object storage, Railway API and worker, Vercel, CircleCI, OpenAI and Anthropic, RPC and DeFi providers, sponsorship/relayers, Resend, and domain/operational expenses. Runtime credentials and public endpoints do not establish an account's billing entitlement or the allocation of shared provider charges. Scope provider records to the service, project and environment before including them in an investor report. Use the original provider currency and a documented USD conversion when required. [Cloud deployment contracts](../deploy/CLOUD.md), [environment contracts](../deploy/ENVIRONMENT.md), [sponsorship configuration](../deploy/GAS-ABSTRACTION.md), [Resend runbook](../deploy/FLIGHT-EMAIL-RESEND.md)

Provider telemetry records live V2 attempts, including tool rounds and failed requests, once per attempt made by the configured transport. The model dimension is the identifier in the provider response. An empty identifier has no canonical attribution. Successful requests mean a usable provider response for metering, while intent validity remains in the interpretation outcome. Browser turn reports and server channel turns remain separately identified in `copilot_daily_metrics`. Exact model rates and complete token dimensions are required for list-price estimates. Estimated usage costs are distinct from provider charges and invoices. OpenAI input includes cached reads. Anthropic input includes uncached input, cache reads, and cache writes when all three dimensions are reported. Reasoning is a subset of output when the provider reports it, so pricing uses output once. The optional daily aggregate stores no prompt, tool content, user, wallet, or conversation identifiers and follows the existing 90-day metrics retention policy. Historical V2 interpretations, MCP tools, Developer API, and legacy V1 have different collection paths and cannot be treated as covered provider requests.

## Wallet export reproduction and acceptance

The pinned Privy SDK opens an in-page provider modal and renders export content in an isolated iframe. FloFi previously kept its own native `showModal()` open until the SDK promise settled on dismissal. Pinned Chromium reproduced the native dialog intercepting pointer input to a provider overlay even at the highest CSS stacking value. This left the provider overlay inaccessible and the FloFi export button pending. The corrected handoff closes the native dialog before the SDK invocation, in the same click. Returning to FloFi restores the confirmation and then focus to the original wallet menu. A stalled SDK invocation stops the loading indicator after 45 seconds and keeps the guard against a second export until settlement or tab reload. The legacy export uses the existing gesture-bound popup on the Turnkey origin. [Privy export documentation](https://docs.privy.io/wallets/wallets/export)

The application export bridge consumes stable errors only. It neither forwards provider exception objects nor collects iframe contents. The signer page policy and cross-origin SDK behavior remain in force. The source audit found no application session-replay or heatmap collector on the export surface. Use an unfunded disposable wallet when verifying actual Privy EVM and Solana export, provider MFA or confirmation, cancellation via Close and Escape, browser settings that block popups, and subsequent wallet-page use on supported browsers. Keep screenshots, traces, recordings, clipboard capture and error-report capture off. Never exercise export using a real customer wallet.

## Operational rollout

Schema `0029_finops_ledger` is staged with an exact forward certificate. The standard migration command continues to ship schema 28 while consumers roll. FinOps presents unavailable ledger data before activation. On a dedicated disposable or preview database, test the exact migration and report workflows before authorizing production activation. On production, the owner first confirms every schema consumer and its operational restart path runs a revision with the 0029 certificate. The owner then runs the existing admin entry point with `finops-migrate` once using the direct database connection. Reapplying exact migration bytes is safe. A revision without the certificate refuses schema 29, so retain compatible rollback builds. [Schema compatibility procedure](../deploy/SCHEMA-COMPATIBILITY.md#21-certificate-0029_finops_ledger)

The optional OpenAI Costs integration uses a fixed GET endpoint and accepts only normalized records for the configured project. Set `FLOFI_FINOPS_OPENAI_ADMIN_KEY`, `FLOFI_FINOPS_OPENAI_PROJECT_ID`, and `FLOFI_FINOPS_BILLING_TENANT` in the server-side production configuration only if the owner approves the provider's organization-level administrative credential. The adapter itself only queries costs. It checks project attribution on every returned result, accepts a bounded set of closed UTC days, and preserves previously reconciled records when a sync fails. Choose invoice import when an organization-level credential is disproportionate or the provider account has costs outside the approved FloFi scope. Billing for Neon, Railway, Vercel, CircleCI, Anthropic, RPC and DeFi APIs, relayers, email, domain, and other operational expenses uses manual entries or CSV in this release. Actual account billing and FX rates must come from the operator's records. [OpenAI Costs API](https://developers.openai.com/api/reference/resources/admin/subresources/organization/subresources/usage/methods/costs)

## Prepare the investor report

1. Sign in to the existing **Admin Console** with a granted administrator wallet and open **Monitor → FinOps & Unit Economics**. Viewer sessions can inspect and export financial reports. Operator sessions can add or reconcile cost records and synchronize available providers.
2. Apply the reporting period. For each provider and service, use FloFi's own allocation and retain the original billing currency, source reference and any applicable conversion rate. Enter reconciled actual fee receipts through the platform-fee accounting scope. Import at most 100 ledger entries per CSV submission. The form lists the fixed headers and the scope catalog.
3. Check provider coverage, synchronization freshness, accounting sources and the **Data quality and methodology** section before sharing. Use verified invoice or accounting records for confirmed actuals. Higher-authority entries supersede overlapping estimates within the same scope and environment. A partial total covers recorded categories and days only. The current-month projection extrapolates covered closed days under a linear accrual assumption.
4. Open **Investor reporting**, fill the assumptions if a growth scenario is needed, and select **Download investor CSV** or **Print or save PDF**. The exported financial report uses aggregates and omits ledger notes, original references and administrator wallet identity. The report and controls follow the interface's English or Portuguese preference. CSV headers and machine-readable quality codes are stable.

Allocated cost per observed chat interaction and completed canonical workflow divides the selected period's identified costs by its observed denominator. The workflow cohort uses canonical multi-step Mainnet records and excludes legacy projections and user-paid network fees from FloFi costs. Distinct active users, complete simulation and approval counts, workflow-linked costs, and eligible transaction notional lack complete source coverage. Detailed V2 provider calls are available from schema activation forward only. The simulator requires each assumption to be entered and uses its own modeled revenue and expenditure. The simulator's other variable work cost excludes AI and sponsored gas because each has its own input.
