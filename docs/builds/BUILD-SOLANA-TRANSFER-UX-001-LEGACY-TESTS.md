# Legacy browser coverage classification — 2026-10-19

**The 16 entries below are spec files, not 16 failed test cases.** None is part of the 44-profile product plan. They were not run in the preceding checkpoint or counted as passes, and no failing baseline run establishes when each became stale. This is a source-based classification, except the dashboard failure, which has an archived failing browser log. Calling every entry an obsolete test or a proven pre-existing failure would overstate the evidence.

The product now accepts Review and requests the first wallet authorization with one `Authorize in wallet` action. `acceptProductReview` does that combined action. Older tests often call it as a Review-only helper, assert zero requests afterward, then drive another protocol-specific Execute button. Those assertions need semantic migration. Public product surfaces also refuse MOCKED execution; weakening that guard to let a legacy happy path run would be a regression.

## Dashboard-foundation failure

`pw-legacy.log` in the prior checkpoint's scratchpad records the failure at `dashboard-foundation.spec.ts:49`: expected `/`, received `/app` after `Build workflow`. The canonical application route and `AppShellContent.setTab` use `/app`; this is also the behavior at baseline HEAD `616598f`. The stale assertion stopped the test before workflow-preservation assertions could execute.

Correcting that URL revealed a second stale assumption: this test configures no swap runtime, but then tries to click the correctly disabled `Simulate workflow` action. It now explicitly asserts that gate is disabled and visits Simulate through stage navigation. The same test checks the `2.5 USDC` draft graph through Dashboard → Build → Simulate → Execute → back navigation, no financial action, and zero wallet signing/submission methods. The focused rerun result is recorded in the audit. This is test drift; no navigation product change or runtime gate weakening was needed. **Retention of an actual completed simulation result through Dashboard is not established by this draft-navigation test.**

The prior broad legacy run also had `MOCK_RESET_DENIED` from an omitted Supply harness and an outdated Simulate-shell expectation; its subsequent correctly configured rerun passed 6/6. Neither is an unresolved product regression.

## Actual regressions and unresolved evidence

The prior checkpoint reproduced and fixed product regressions A7 (`/connections` 500), A8 (duplicate sign-in), and A10 (silent Solana reconnect overriding the explicit network switch). This continuation fixes A13 (simulation mislabeled as execution) and the newly identified receipt projection defect (summary `hasEvidence` trusted despite a failed/missing/divergent evidence read). No executed legacy browser trace in this continuation proves another product regression. **Their protocol-specific successful execution and recovery journeys remain a certification gap**, even with 44/44 product profiles and green units. The profiles deliberately cover many MOCKED refusal boundaries; those are not positive execution certificates. Do not retire useful financial assertions based solely on old labels or counts. Migrate them to the current product journey with an explicitly isolated transport, or retain them as engineering/service diagnostics with an appropriate Review-only helper. Any future expansion of paid certification scope needs owner agreement; the optimized CircleCI plan is unchanged here.
