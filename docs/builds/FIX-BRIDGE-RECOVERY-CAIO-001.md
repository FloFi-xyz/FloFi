## Demonstrated defects and implemented recovery

1. **Wallet reports rejected at the cloud boundary:** PR #130's directed and Universal Bridge clients send `attemptId` in HASH/UNKNOWN reports. The backend's strict two-field validator refused it with `ARGUMENTS_INVALID`, before persistence. A real PostgreSQL regression reproduced this failure. Bridge-specific validators now accept a bounded attempt identifier, preserve the strict remaining field allowlist, and delegate the exact identity comparison to the existing durable service. A stale approval report cannot attach to the deposit. Legacy reports remain compatible. This is a demonstrated mechanism consistent with the incident; the original browser HTTP response was not retained, so its individual failure is not claimed as captured evidence.
2. **Optional source log discovery blocked exact nonce discovery:** the incident's public Base `eth_getLogs` request reproducibly returned HTTP 429. The old service retried that method before attempting nonce discovery, matching the worker's approximately 34-second failures. Exact wallet/chain/nonce/target/calldata/value recovery now runs first. Log discovery remains available for delegated submissions.
3. **Recovered hash not durable before the next RPC:** a nonce-discovered hash used to reach the receipt RPC before `save`. It is now persisted first. An isolated fault between those operations leaves a PENDING attempt with its hash; a fresh process resumes it without wallet calls.
4. **No independent configured path:** directed and Universal Bridge clients now use bounded, chain-bound read failover, including the already configured server-side Alchemy credential and optional HTTPS `GRYLOO_<NETWORK>_FALLBACK_RPC_URLS`. Each path has a 3-second transport timeout; at most four distinct paths are accepted. The durable worker retains its existing bounded backoff and exhaustion policy. Wrong-chain answers, reverts and malformed responses fail closed. No signing or sending method was added.
5. **Pruned historical state blocked final evidence:** the isolated replay reached DESTINATION_OBSERVED but Arbitrum public RPC returned `missing trie node` for a block-pinned balance read. That classified availability failure can now use an archive-capable configured provider, with the identical call and block. No substitution of latest state or relaxation of finality is allowed.
6. **Temporary failures had no directed-Router outcome:** the service reloads the latest durable snapshot after an observation outage and records TEMPORARY_FAILURE separately from financial truth. Execute and saved History reuse that message and the retained costs. Unchanged observations are coalesced to preserve existing journal growth protections. Manual status reads have a 30-second UI deadline; a late old response cannot unlock a newer check. The control shows its last completed read time.

The exact incident's **private local snapshot copy** was successfully reobserved with execution disabled: RECONCILED, source debit 1 USDC, actual destination credit 0.988966 USDC, source/destination canonical inclusion and finality, and an evidence bundle. No production database was connected by that rehearsal. Its temporary live test was removed; mandatory CI uses isolated engineering fixtures exclusively. Public facts and restricted evidence digests are in [the evidence manifest](FIX-BRIDGE-RECOVERY-CAIO-001-EVIDENCE.json).
