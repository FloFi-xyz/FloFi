## What 0031 allows, and what it never allows

Deletable (owner request, through the existing authenticated History action): a Uniswap position-management run whose every historic snapshot is
an unstarted simulation — no authorization ever recorded, no attempt, no observed result, no evidence, verdict `PENDING` — and which no lease,
work item, INTENT log (position claim, owner-nonce reservation), recovery link, handoff or journal transition references.

Always kept: authorized (even if later invalidated), prepared, signed, submitted, uncertain, confirmed, reverted, divergent, partially or fully
reconciled runs and their evidence; anything another tenant or owner holds; any run a worker may still observe. Tombstones stay immutable and a
purged identity can never be recreated (`EXECUTION_DELETED`).

## Rollback

- **Before activation:** any build is a rollback target exactly as before (schema unchanged).
- **After activation, application rollback:** only to a build carrying this certificate (this release or later). An older build refuses schema 31
  (`MIGRATION_HISTORY_MISMATCH`) and must not be deployed. Financial observation and reconciliation continue throughout. Once 0032 is also active
  ([RELEASE-SINGLE-STEP-RUNS-0032.md](./RELEASE-SINGLE-STEP-RUNS-0032.md)), only a build carrying the 0029–0032 certificate is a rollback target.
- **Stop new deletions without touching the schema:** set the existing `FLOFI_OWNER_HISTORY=read-only` (deletions and archives answer
  `HISTORY_READ_ONLY`; no record changes). This build changes no environment variable; this is the existing switch.
- **Emergency reversal (owner decision, last resort):** run `RELEASE-POSITION-PURGE-0031.reversal.sql` in one transaction with the migration
  connection. It takes the migration runner's advisory lock, refuses unless 0031 (exact identity) is the newest migration, restores 0016's predicate byte for byte and removes only the 0031
  ledger row, after which the pre-0031 certificate serves the database again. Position runs deleted while 0031 was active stay deleted (their
  tombstones are immutable); nothing else is touched. Proven on disposable PostgreSQL by `certificate-0031.pg.test.ts`.
- Never restore deleted runs, edit the audit, or run ad hoc DDL.
