# Infrastructure and CI/CD

- Trace Vercel Web to its configured embedded or Railway remote backend and distinguish Preview from production. Hosted prerequisites fail closed when missing. Railway API and worker are separate services with explicit environment and readiness contracts. Remove readiness before drain, stop taking new work, finish accepted handlers or release work through durable lease semantics, then close shared resources. Verify the native Node TypeScript entrypoint with explicit runtime imports and type-only edges. A Next/Vitest build is a separate check. [Vercel config](../../../apps/reference-dapp/vercel.json) · [Railway API](../../../deploy/railway/api.railway.json) · [Railway worker](../../../deploy/railway/worker.railway.json) · [Native Node closure](../../../apps/reference-dapp/backend/plain-node-closure.test.ts)
- Work on a named branch in the isolated worktree. Fetch current main and account for concurrent PRs. Keep credentials, environment changes and deployment authority with the owner. Trace a release or rollback to the exact Git SHA, artifact digests, dependency and lockfile identity, service/environment and compatible schema. Check health/readiness and redacted logs before and after diagnosing an incident. Application rollback does not reverse schema or external effects. [Cloud runbook](../../../docs/deploy/CLOUD.md) · [Database compatibility](../neon-postgresql/SKILL.md)
- GitHub review and branch protection govern merge. CircleCI certification fans in the complete ledger for the same SHA, including the supply-chain, unit, PostgreSQL, fork and all eight browser jobs. Prove the build archive and workspace provenance for browser consumers. Inspect every failed job and consolidate deterministic fixes before pushing. Use at most one failed-jobs-only rerun of the same SHA for a proven transient failure. A revision with an existing pipeline needs no manual duplicate.
