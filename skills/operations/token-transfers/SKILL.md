# Token standards and transfers

- A native transfer carries value, an ERC-20 transfer uses contract calldata, and allowance delegates spending to a specific spender. Resolve network, contract/mint, token program and decimals before computing positive integer base units. Keep wrapped and native assets distinct. An ERC-20 allowance, balance or provider metadata alone cannot prove receipt. Validate the exact recipient, amount, allowance when relevant, gas or rent, expected debit and credit. Never infer a supported route from a token symbol or the existence of a standard. [EVM compiler](../../../packages/reference-compiler/src/native-transfer.ts) · [Asset registry](../../../packages/action-registry/src/asset-registry.ts)
- Solana's registered system and token transfers are separate. Resolve the mint and owning SPL Token or Token-2022 program from chain state, verify decimals and both token accounts, and validate the canonical associated token account and recipient. Idempotent destination account creation can still affect reviewed rent. The direct path refuses wrapped SOL and limits Token-2022 to verified extension combinations, with an explicit permanently-zero transfer-fee exception. Other fee schedules, extensions or transfer restrictions stay out unless a current path explicitly supports them. [Solana compiler](../../../packages/reference-compiler/src/solana-transfer.ts) · [Transfer regressions](../../../apps/reference-dapp/src/server/solana-transfer-service.test.ts)
- Keep normal sequential composition, supported reviewed atomic wallet batches and ERC-4337 groups distinct. A later swap→transfer step consumes the reconciled output, and a bridge→transfer consumes verified destination delivery. An atomic batch has its own supported bound, output minimum and topology checks. The stored ERC-4337 group refuses some swap→transfer topologies supported by the wallet batch. [Batch tests](../../../apps/reference-dapp/src/user-funded/universal-batch.test.ts) · [Group tests](../../../apps/reference-dapp/src/user-funded/groups.test.ts)
- Keep durable submission and reconciliation tied to the exact authorized transfer. A wallet-relayed ERC-20 transfer can settle without consuming the owner's EOA nonce. Verify the supported relay path and owner token debit and recipient credit. Refuse divergent relayed native value and keep unknown outcomes open until evidence resolves them. Review the [execution lifecycle](../execution/SKILL.md) and [account abstraction](../account-abstraction/SKILL.md) when the selected path uses them.
