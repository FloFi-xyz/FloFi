# 0x Protocol

- 0x Swap v2 returns an executable transaction for the taker to send, with AllowanceHolder or Permit2 allowance variants. Gasless v2 can return typed approval and trade requests for relayer submission. FloFi uses only `/gasless/chains`, `/gasless/quote`, `/gasless/submit` and `/gasless/status/:tradeHash`. The branch sits under the existing Robinhood swap profile and has no separate capability tuple. Native-fee Robinhood swaps use the Uniswap V3 path. [Client](../../../apps/reference-dapp/src/server/zeroex-gasless/client.ts) · [Gas policy](../../operations/gas-abstraction/SKILL.md)
- Eligibility is deployment-gated for chain 4663, a plain EOA, confirmed native shortfall, ERC-20 legs and a validated pair and provider route. Use the fresh FloFi V3 quote for the reviewed economic floor. Validate asset addresses, taker, amounts, minimum, recipients, quote and typed-data deadlines, chain and canonical Permit2/Settler pins. If approval is needed, verify its supported form (including EIP-7597 where applicable) and Permit2 target. The eligible provider path can request unlimited Permit2 allowance and must disclose it in Review. Bind the Permit2 witness, nonce, typed domain and trade through the wallet handoff. [Quote verifier](../../../apps/reference-dapp/src/server/zeroex-gasless/quote.ts) · [Wallet verification](../../../apps/reference-dapp/src/wallet/zeroex-gasless-signing.ts)
- Show gas and 0x fees separately in the trade's reviewed denomination and amounts. Reject nonzero transfer taxes, incomplete simulation and missing or zero gas fees. This branch has no FloFi integrator fee or operator sponsorship. Keep the provider key server-side and preserve status distinctions for rate limits, unavailable network or pair and malformed responses. An unavailable relayer or expired quote cannot authorize a different route or payer. [Transport](../../../apps/reference-dapp/src/server/zeroex-gasless/transport.ts)
- Fence the attempt durably before the submission call. Recover uncertainty by polling the trade hash and reconcile the relayer's successful transaction to the validated Settler, the Permit2 nonce transition, and the owner's expected debit and credit. Provider status alone cannot prove settlement. A consumed nonce without matching evidence stays untraced. Test stale data, unexpected allowance, replay, duplicate submission, provider faults and ambiguous receipt recovery with local fixtures.
